# Spark + Scala distributed preparation

`DocumentETL` validates provenance, reports malformed JSONL records, rejects invalid or duplicate chunk IDs, repartitions chunks, and writes real Parquet datasets. With the evidence directory generated by the Python processor it also writes deduplicated entities, relationships, graph nodes, graph edges, document-to-entity mappings, document aggregates, and run metrics.

The extraction boundary is deliberate: run the Python evidence processor first so spaCy loads once per bounded batch, rather than starting a heavyweight model per Spark row. Spark then executes the distributed deterministic transformation and graph preparation work.

Prerequisites: compatible Java, sbt, Spark 3.5.1 and Scala 2.12.18. The job has not been compiled or executed in the current Windows environment because these runtimes are absent.

```powershell
cd spark-scala
sbt package
spark-submit --class DocumentETL --master "local[*]" target/scala-2.12/distributed-document-intelligence-etl_2.12-0.1.0.jar ../data/processed/chunks.jsonl ../data/spark-output 4 ../data/evidence
```

The evidence directory argument is optional. For a cluster, use shared storage paths and a cluster master URL. Output paths must not already exist. Compare the same input hash across `local[1]`, `local[*]`, and a cluster; retain each adjacent `-metrics` output. These measurements are local-mode unless a multi-worker cluster was actually used; no speedup is claimed by the job.
